# zc-snare

Public build backend for the ZC SNARE EXTRACT pen. No login anywhere: the page uploads the song to tmpfiles.org (anonymous, deleted after 60 min), posts a one-line job note to a public ntfy.sh topic, and this repo's `intake` workflow (a standing listener subscribed to the topic, `pipeline/listen.py`; it hands off to a fresh runner before GitHub's 6 h job cap, and a 5-minute cron restarts it if a hand-off is ever lost - note GitHub's cron is best-effort and never fired in this repo's first 90 min, which is why the listener exists) fetches the song, stages it as a short-lived Actions artifact and starts `extract`. Results are committed to `packs/<id>/` and the page reads them from raw.githubusercontent.com. Songs are never committed to the repo; the artifact is deleted when the pack is published.

Pipeline (identical for every song, nothing tunable per song): ffmpeg decode -> Demucs htdemucs (drums) -> MDX23C DrumSep (kick/snare/toms/hh/ride/crash, checkpoint sha256-verified) -> `build_pack.py --realvel` (per-band auto: real quiet hits where the record has them, flagged estimates where it does not) -> per-file QC with re-pick -> measurement gates -> pack. See `pipeline/run_job.py` for the gates. `golden/<input sha256>.json` holds the local reference result for the four known inputs; a known song must reproduce the loud (hard) picks (>= 3/4), hits-aligned within 30%, correlation within 0.10, mid-band T60 within 30%, and keep hard 4 / medium >= ref-1 real hits, or the run fails. Soft/ghost counts are reported, not gated (they sit near the stem floor and are not bit-reproducible across CPUs). `reference/` holds the four shipped, hand-verified v3 packs the page loads as built-ins; `packs/` is pipeline output only.

Layout: `pipeline/` code, `golden/` reference results, `reference/` shipped packs, `queue/<id>.json` claimed jobs (deleted when published), `packs/<id>/` results (report.json always; zip/oneshot/info/README only when every gate passes). Pushing `jobs/<id>/input.<ext>` by hand also triggers `extract`.

GitHub disables scheduled workflows after 60 days without repo activity, and an Actions outage can break the listener chain; if the page says a job has waited more than a few minutes, run the `intake` workflow once from the Actions tab (that restarts the chain). Put a file named `LISTENER_OFF` at the repo root to fall back to cron-only mode.

Golden gate (the 4 known songs, `golden/<input sha256>.json`, built on the 2-CPU build machine): the 4-CPU hosted runner reproduces them within hard-pick overlap 2/4..4/4 (same loud strokes, order differs), hits_aligned within 10%, corr_median within 0.04, mid-band T60 within 0.25 s (measured 2026-11-06 on Limp Bizkit and Architects). The gate limits are set from that: hard picks >= 2/4 same strokes at <= 1.5 dB level difference, hits_aligned +-30%, corr +-0.10, hard 4 / medium >= golden-1, T60 +-30% or 0.25 s. Soft and ghost membership is reported, not gated: those bands sit near the stem floor and flip between runs.
